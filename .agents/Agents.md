# Project Overview: World Model Sandbox

## Purpose
The primary purpose of this project is to experiment with world models. Specifically, it currently focuses on experimenting with **JEPA** (Joint Embedding Predictive Architecture), based on the paper: https://arxiv.org/abs/2603.19312. 

## Repository Tour
The project is structured around the `src/` directory, which contains several key packages and entry points:

- **`src/algorithms/`**: Contains the implementations of the machine learning algorithms. Currently includes implementations for `jepa` (the encoder) and `jepa_decoder` (for predicting state observations from latent representations), along with base abstractions like `algorithm.py` and `algorithm_factory.py`.
- **`src/datasets/`**: Includes dataset generation scripts and dataset abstractions. It provides tools to generate state-action datasets from an MDP (`dataset_from_mdp.py`) and dataset of latent representations generated by a trained encoder (`dataset_from_encoder.py`).
- **`src/mdp/`**: Contains code for interacting with Markov Decision Processes. Includes Gymnasium environment wrappers (`mdp_gym_writable.py`) and policies (like `uniform_policy.py`) used for collecting interaction data.
- **`src/log/`**: Contains logging utilities for tracking experiments (e.g., Weights & Biases integration).
- **`src/train.py`, `src/evaluate.py`, `src/visualise.py`**: The main entry points for training models, evaluating their performance, and visualizing their predictions.

Other notable directories:
- **`hyperparameters/`**: Stores JSON configuration files for various model hyperparameter setups.
- **`saved_networks/`**: The output directory where trained models (encoders and decoders) are stored.

## Build System
This project uses **`uv`** as its package manager and environment resolver. 
The build system and dependencies are configured in the **`pyproject.toml`** file, which uses the `hatchling` build backend. Commands for training, evaluating, and dataset generation are run via `uv run python -m ...`.

## Workflows
As detailed in the `README.md`, the standard workflow consists of the following steps:
1. **Generate a dataset from the MDP**: Run a policy in a Gymnasium environment to collect state-action transitions.
2. **Train the JEPA encoder**: Train the base JEPA architecture on the generated state-action dataset.
3. **Generate an encoder dataset**: Use the trained JEPA encoder to convert the state-action dataset into a dataset of latent representations (for training the decoder).
4. **Train the JEPA decoder**: Train the decoder on the encoder dataset to reconstruct observations from latent representations.
5. **Visualise/Evaluate**: Use `src.visualise` and `src.evaluate` to inspect and quantify the performance of the trained models.

## Dependencies & Sibling Repositories
